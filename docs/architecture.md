# Архитектура (черновик v0.1)

## Требования

- Статический сайт на GitHub Pages, без своего сервера.
- Связь между игроками через MQTT-брокер (WebSocket поверх TLS, `wss://`):
  страница отдаётся по HTTPS, поэтому браузер не пустит `ws://`.
- У каждого игрока свой телефон. Интерфейс в первую очередь мобильный.
- Позже добавится общий экран (планшет) в режиме «только просмотр». Игра должна
  работать и без него.

## Стек

- **TypeScript + Vite**: сборка в статику, деплой в GitHub Pages через Actions.
- **Preact**: лёгкий UI, на телефоне грузится быстро.
- **Playwright**: сквозной тест партии через интерфейс (`npm run e2e`).
- **mqtt.js**: клиент MQTT через WebSocket.
- **Vitest**: тесты игрового движка.

## Модули

```
src/
  engine/     чистая игровая логика без UI и сети
    state.ts    типы состояния
    rules.ts    reducer: (state, action) => state
    payment.ts  расчёт оплаты: свои ресурсы, торговля, выбор ресурса
    scoring.ts  подсчёт очков
    rng.ts      детерминированный ГПСЧ с seed
  worlds/     миры: тема, в которой играют по общим правилам
    ancient/      «Древний мир»: world.json и картинки рядом
    README.md     формат мира
  net/
    mqtt.ts     подключение, топики, сериализация
    host.ts     логика хоста
    client.ts   логика игрока
  ui/           экраны: лобби, рука, город, соседи, итог
```

Правила (эпохи, торговля, войны, подсчёт очков) общие. Всё тематическое —
ресурсы и их значки, научные школы, цивилизации, карты — задаёт **мир**:
папка в `src/worlds` с `world.json` и картинками. Хост выбирает мир в лобби,
он попадает в состояние игры (`world`).

Движок полностью детерминирован и не зависит от UI и сети. Его можно покрыть
тестами и прогнать целую партию ботами без браузера.

## Сетевая модель: авторитетный хост

Один из телефонов создаёт комнату и становится **хостом**. Только он
применяет действия к состоянию. Остальные отправляют ему ходы и получают от
него обновлённое состояние.

Топики (`<room>` — случайный код комнаты из 5 символов, например `K7QXM`):

| Топик | Кто пишет | Retained | Содержимое |
|---|---|---|---|
| `epoch-draft/<room>/lobby` | хост | да | хост, список игроков (в том числе ботов), начата ли игра |
| `epoch-draft/<room>/join/<playerId>` | игрок | да | имя игрока (запрос на вход и переименование) |
| `epoch-draft/<room>/public` | хост | да | общее состояние: города, монеты, эпоха, ход, кто уже выбрал |
| `epoch-draft/<room>/hand/<playerId>` | хост | да | рука игрока, принятый выбор, ошибка |
| `epoch-draft/<room>/action/<playerId>` | игрок | да | выбор на ход с номером эпохи и хода |
| `epoch-draft/<room>/presence/<playerId>` | игрок | да (+ LWT) | `"online"` / `"offline"` |
| `epoch-draft/<room>/host` | хост | да | полное состояние хоста для продолжения после перезагрузки |

- Retained-сообщения означают, что после перезагрузки страницы или обрыва
  связи телефон сразу получает актуальное состояние.
- LWT (Last Will) показывает, кто отвалился.
- Хост публикует своё полное состояние в `host`, поэтому после перезагрузки
  страницы партия продолжается с того же места.
- Действия retained и помечены эпохой и ходом: если хост был офлайн, он получит
  последний выбор игрока при подключении, а устаревшие выборы проигнорирует.
- Боты живут на хосте и ходят сразу, как только начинается ход.
- Варианты оплаты клиент считает сам тем же движком по общему состоянию и своей
  руке; хост перепроверяет каждый ход.
- Общий экран в будущем просто подпишется на `public`, без изменений протокола.

**Приватность рук** обеспечивается только соглашением: клиент подписывается
на свой топик. Для семейной игры этого достаточно. Технически любой, кто
знает код комнаты, может прочитать все топики.

## Брокер

Адрес брокера и токен задаются в настройках приложения и хранятся в
`localStorage`. По умолчанию адрес `wss://mqtt.flespi.io`, токен передаётся как
имя пользователя MQTT. Токен можно передать в ссылке-приглашении (`#t=...`):
приложение сохранит его и уберёт из адресной строки. Варианты:

- свой Mosquitto с WebSocket-листенером и TLS;
- публичный тестовый брокер (для разработки; без гарантий и без приватности).

## Формат карты

```json
{
  "id": "I-quarry",
  "name": "Каменоломня",
  "epoch": 1,
  "type": "raw",
  "minPlayers": [3, 5],
  "cost": { "coins": 1 },
  "effects": [{ "produce": { "stone": 1 } }],
  "chainsTo": ["II-fortress"]
}
```

- `minPlayers` — при каком числе игроков добавляется очередная копия: `[3, 5]`
  значит одна копия при 3+ игроках и вторая при 5.
- `effects` — список эффектов из фиксированного набора: `produce`,
  `produceChoice`, `points`, `coins`, `military`, `science`, `tradeDiscount`,
  `pointsPer` (за карты/стадии у себя и/или у соседей) и т. п.
- `chainsTo` — какие карты эта карта позволяет построить бесплатно.

## План работ

1. Движок + типы + тесты, партия из ботов в консоли.
2. Колода и цивилизации (`src/worlds/ancient/world.json`), прогон баланса
   ботами.
3. Сеть: лобби, хост, клиенты.
4. Мобильный UI.
5. Деплой на GitHub Pages.
6. (Позже) общий экран.
