# Архитектура (черновик v0.1)

## Требования

- Статический сайт на GitHub Pages, без своего сервера.
- Связь между игроками через MQTT-брокер (WebSocket поверх TLS, `wss://`):
  страница отдаётся по HTTPS, поэтому браузер не пустит `ws://`.
- У каждого игрока свой телефон. Интерфейс в первую очередь мобильный.
- Позже добавится общий экран (планшет) в режиме «только просмотр». Игра должна
  работать и без него.

## Стек

- **TypeScript + Vite**: сборка в статику, деплой в GitHub Pages через Actions.
- **Preact**: лёгкий UI, на телефоне грузится быстро.
- **Playwright**: сквозной тест партии через интерфейс (`npm run e2e`).
- **mqtt.js**: клиент MQTT через WebSocket.
- **Vitest**: тесты игрового движка.

## Модули

```
src/
  engine/     чистая игровая логика без UI и сети
    state.ts    типы состояния
    rules.ts    reducer: (state, action) => state
    payment.ts  расчёт оплаты: свои ресурсы, торговля, выбор ресурса
    scoring.ts  подсчёт очков
    rng.ts      детерминированный ГПСЧ с seed
  worlds/     миры: тема, в которой играют по общим правилам
    ancient/      «Древний мир»: world.json и картинки рядом
    README.md     формат мира
  net/
    mqtt.ts     подключение, топики, сериализация
    host.ts     движок комнаты: применяет ходы и команды ведущего
    server.ts   сервер игр: движки комнат, переданных на его код
    client.ts   логика игрока и команды ведущего
  ui/           экраны: лобби, рука, город, соседи, итог
```

Правила (эпохи, торговля, войны, подсчёт очков) общие. Всё тематическое —
ресурсы и их значки, научные школы, цивилизации, карты — задаёт **мир**:
папка в `src/worlds` с `world.json` и картинками. Ведущий выбирает мир в лобби,
он попадает в состояние игры (`world`).

Движок полностью детерминирован и не зависит от UI и сети. Его можно покрыть
тестами и прогнать целую партию ботами без браузера.

## Сетевая модель: ведущий и движок

Роли в комнате две:

- **Ведущий** — игрок, создавший комнату. Он управляет ею: мир, способ выдачи
  цивилизаций, боты, порядок мест, старт, завершение хода, замена игрока
  ботом. Всё это он отправляет командами.
- **Движок** — единственный, кто применяет ходы, входы и команды к состоянию
  и публикует результат. Работает на телефоне ведущего (по умолчанию) или на
  **сервере игр**: вкладке той же страницы с `#serve` или процессе
  `npm run serve`. У сервера свой код; ведущий запоминает его в настройках
  (они хранятся на брокере) и передаёт игру туда кнопкой. Новая комната сама
  уходит на сервер ведущего, если тот в сети.

Кто движок, решает ведущий: топик `engine`. Движок, увидевший там чужой id,
сразу замолкает. Новый движок берёт полное состояние из `host` и заново
читает retained-входы игроков и очередь команд, так что недошедшее до `host`
применяется ещё раз (команды — по номеру `seq`, ходы — по эпохе и ходу).
Опоздавшее сообщение прежнего движка новый перекрывает своим состоянием.

Топики (`<room>` — случайный код комнаты из 5 символов, например `K7QXM`):

| Топик | Кто пишет | Retained | Содержимое |
|---|---|---|---|
| `epoch-draft/room/<room>/engine` | ведущий | да | `{id, owner}`: кто движок (id ведущего — его телефон, иначе код сервера) и кто ведущий |
| `epoch-draft/room/<room>/cmd` | ведущий | да | очередь команд `{list: [{seq, op, ...}]}`, ещё не применённых движком |
| `epoch-draft/room/<room>/lobby` | движок | да | ведущий, движок, номер последней применённой команды (`cmdSeq`), список игроков (в том числе ботов), начата ли игра, окончена ли она (`over`) |
| `epoch-draft/room/<room>/join/<playerId>` | игрок | да | имя игрока (запрос на вход и переименование) |
| `epoch-draft/room/<room>/public` | движок | да | общее состояние: города, монеты, эпоха, ход, кто уже выбрал, журнал всех ходов (`log`) и конфликтов (`battles`) |
| `epoch-draft/room/<room>/hand/<playerId>` | движок | да | рука игрока, принятый выбор, ошибка |
| `epoch-draft/room/<room>/action/<playerId>` | игрок | да | выбор на ход с номером эпохи и хода |
| `epoch-draft/room/<room>/host` | движок | да | полное состояние движка, чтобы любой движок продолжил партию |
| `epoch-draft/room/<room>/closed` | любой участник | да | кто завершил игру; остальные retained-сообщения комнаты удаляются |
| `epoch-draft/player/<playerId>/presence/<room>` | игрок | да (+ LWT) | `"online"` / `"offline"` |
| `epoch-draft/server/<code>/presence` | сервер | да (+ LWT) | `"online"` / `"offline"` |

Присутствие лежит вне комнаты: вход в комнату ничего в ней не меняет, если
игроку там нечего делать (завершённая партия, чужая идущая игра). У каждой
комнаты оно своё, поэтому вкладки с разными комнатами не перетирают друг
друга.

Код комнаты состоит из букв, цифр, `-` и `_`.

- Retained-сообщения означают, что после перезагрузки страницы или обрыва
  связи телефон сразу получает актуальное состояние.
- LWT (Last Will) показывает, кто отвалился.
- Движок публикует своё полное состояние в `host`, поэтому после перезагрузки
  страницы или смены движка партия продолжается с того же места.
- Действия retained и помечены эпохой и ходом: если движок был офлайн, он
  получит последний выбор игрока при подключении, а устаревшие выборы
  проигнорирует.
- Боты живут в движке и ходят сразу, как только начинается ход. Если кроме
  ведущего играют одни боты, движок завершает ход сам.
- Варианты оплаты клиент считает сам тем же движком по общему состоянию и своей
  руке; движок перепроверяет каждый ход.
- Главный экран подписан на `epoch-draft/+/lobby` и `epoch-draft/+/closed` и
  показывает все незакрытые комнаты: в них можно войти или удалить комнату (как
  «Завершить игру для всех»: `closed` и очистка всех retained-топиков комнаты).
- Общий экран в будущем просто подпишется на `public`, без изменений протокола.

**Приватность рук** обеспечивается только соглашением: клиент подписывается
на свой топик. Для семейной игры этого достаточно. Технически любой, кто
знает код комнаты, может прочитать все топики.

## Брокер

Адрес брокера и токен задаются в настройках приложения и хранятся в
`localStorage`. По умолчанию адрес `wss://mqtt.flespi.io`, токен передаётся как
имя пользователя MQTT. Токен можно передать в ссылке-приглашении (`#t=...`):
приложение сохранит его и уберёт из адресной строки. Варианты:

- свой Mosquitto с WebSocket-листенером и TLS;
- публичный тестовый брокер (для разработки; без гарантий и без приватности).

## Формат карты

```json
{
  "id": "I-quarry",
  "name": "Каменоломня",
  "epoch": 1,
  "type": "raw",
  "minPlayers": [3, 5],
  "cost": { "coins": 1 },
  "effects": [{ "produce": { "stone": 1 } }],
  "chainsTo": ["II-fortress"]
}
```

- `minPlayers` — при каком числе игроков добавляется очередная копия: `[3, 5]`
  значит одна копия при 3+ игроках и вторая при 5.
- `effects` — список эффектов из фиксированного набора: `produce`,
  `produceChoice`, `points`, `coins`, `military`, `science`, `tradeDiscount`,
  `pointsPer` (за карты/стадии у себя и/или у соседей) и т. п.
- `chainsTo` — какие карты эта карта позволяет построить бесплатно.

## План работ

1. Движок + типы + тесты, партия из ботов в консоли.
2. Колода и цивилизации (`src/worlds/ancient/world.json`), прогон баланса
   ботами.
3. Сеть: лобби, движок, клиенты.
4. Мобильный UI.
5. Деплой на GitHub Pages.
6. (Позже) общий экран.
